# Audit report

What is this file? The report of one audit. The auditor fills it at a gate. The auditor reads documents, code, history and logs, checks every claim, counts what can be counted and puts evidence first. The auditor fixes nothing and never closes its own finding.

## Audit G2
- Read: `TASKS.md`, `DECISIONS.md`, `LOG.md`, `STATUS.md`, `src/billing/`, `src/api/`, `tests/`, the git history of phase 2.

## Findings

### P-1 Status page one task behind
- Type: process
- Severity: medium
- Claim: `STATUS.md` answers "where are we" on its own.
- Evidence: `STATUS.md` names T-4 as the last task; `TASKS.md` marks T-5 done.

### D-1 Invoice number counter overflows
- Type: design
- Severity: high
- Claim: the numbering design holds for the expected volume.
- Evidence: DEC-004 sets a four-digit counter per year; the load test data of 12,000 invoices overflowed it.

### C-1 Tax rate lookup falls back to zero
- Type: code
- Severity: high
- Claim: an unknown country gives an error.
- Evidence: `src/billing/tax/rates.py` line 41 returns 0 for an unknown country code; no test covers it.

### C-2 Unused import in the invoice module
- Type: code
- Severity: low
- Claim: the code passes the linter.
- Evidence: the linter reports 1 unused import in `src/billing/invoice.py`.

### S-1 API key header written to the request log
- Type: security and privacy (S-)
- Severity: high
- Claim: no secret is written to a log.
- Evidence: `src/api/middleware/logging.py` line 18 logs all request headers, including `X-Api-Key`.
