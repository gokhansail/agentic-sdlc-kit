## 3. G2 gate criteria (proposal; the verdict is `auditor-mini`'s)

1. Reproduce: on the maintainer's machine, from a clean checkout of the gate commit, `auditor-mini` reruns `python -m tools.metrics` on each snapshot named in the manifests, then `render`. Pass: input hashes match the manifests and `git status --porcelain evidence/ EVIDENCE.md` prints nothing.
2. Three hand counts, exact equality, counted from the source files and `git log` without the scripts:
   - H1 Project A, v2: number of version headings with the "to be tested" marker (changelog parser, folded marker).
   - H2 Project A, v2: review-round distribution over the work log metric lines (the parser with the most phrasings).
   - H3 Project B, v1: commits per ISO week (git path, second source).
   `auditor-mini` may replace one with a pick of its own and says why.
3. Limits section holds at least: n = 1 maintainer and no causal claim (DEC-010); process and maintainer changed together; B has v1 data only and which metrics are A-only; period lengths in days and entries per column; M5, M6 and M13 are self-reported by the role being measured; A's records entered git just before the cutoff, so v1 record text is today's text; definitions that changed over time (round 0); dropped metrics and why; snapshot date and the cells shown as counts only (D-25).
4. Tests: `python -m pytest -q` green; each kept metric has a fixture test with a known answer; a determinism test; a test that the JSON writer refuses a free-text value.
5. Privacy: guard exit 0 over the tree and the phase 2 commits; `evidence/*.json` holds only fixed keys, numbers, dates, hashes and the labels "project-a", "project-b", "kit".
6. Parse coverage: per source, lines that match the loose metric-line pattern minus lines parsed; 0, or the count is in the limits section.

## 4. Technical base

- Structure: `tools/metrics/` run as `python -m tools.metrics --source <dir> --profile <file> --label <name> --out evidence/<name>.json`; `tools/` stays without `__init__.py` (namespace package, Python 3.10). Tests in `tests/metrics/`, fixtures in `tests/fixtures/metrics/`.
- Standard library is enough: `re`, `json`, `unicodedata`, `hashlib`, `subprocess` (git), `datetime`, `argparse`, `pathlib`. No spreadsheet parsing (B's board is dropped). No new line in `requirements-dev.txt`.
- Marker words (D-22): input text is folded before matching: NFKD, drop combining marks, map the dotless i, casefold. Profiles hold folded ASCII markers as regexes, one JSON per source. Folding also absorbs the sources' own inconsistent use of diacritics. Fixtures use invented English markers, plus one folding test whose letters are built with `chr()`.
- Inputs (D-24): `--snapshot` copies the named record files into `evidence/raw/<label>/` (ignored, rejected by the guard) and writes a manifest; git metrics stop at the recorded HEAD.
- Output schema (`evidence/<label>.json`): `schema` (1), `label`, `cutoff`, `kit_commit`, `input` {`head`, `dirty`, `files` {role: sha256}, `profile_sha256`}, `metrics` {M-id: {`v1`, `v2`: {`n`, `count` or `distribution`}, `status`: "ok" | "no data"}}, `warnings` {name: count}. Sorted keys, no timestamps, so a rerun is byte-identical.
