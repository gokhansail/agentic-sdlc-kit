### D-35 Scope guard: states and who it binds

Data: `CLAUDE.md` places the active contract in `.sdlc/`. DEV_RULES 7: Markdown is the source of truth and the only other store is `.sdlc/metrics.jsonl`. `templates/task-contract.md` says `Files in` and `Files out`; `TASKS.md` uses `Touch` and `Do not touch` in 17 lines and the template names in none. Recommended design, option a:

| State | Test | Result for `Write`, `Edit`, `NotebookEdit` |
|---|---|---|
| Not opted in | no `.sdlc/project.md` in the project root | allow, silent, before Python starts |
| Opted in, no contract | no `.sdlc/active-contract.md` | deny, except the always-allowed list |
| Active contract | file parses | allow `Files in` and the always-allowed list; deny the rest; `Files out` wins over both |
| Broken contract | no path token in `Files in`, or a parse error | deny; the reason names the line |

- `.sdlc/project.md` is the opt-in and the one config file: a record map (status, tasks, log, decisions, changelog), the developer rules file, the language for reports, and always-allowed globs (records, reports, tests and fixtures). `/sdlc:init` writes it.

- A path outside the root is denied in every state but the first. Case-insensitive on Windows, with `/` and `\` unified.
- Binding: every writer in the session, since the scribe and the TL pass through the always-allowed list. If P-30 shows that hook input names the sub-agent (V-4), sub-agents also cannot write `.sdlc/`. If not, a developer can widen its own scope with an `Edit` of the contract. That becomes a stated limit, and the TL's diff review covers it.

- The active file is a copy of one contract, removed at task end. `PLAYBOOK.md` lesson 5 says one place; it stays transient because other projects name their task file differently.
